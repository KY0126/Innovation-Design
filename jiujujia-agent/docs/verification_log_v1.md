## 三、還沒驗證的部分（要在你電腦上跑）

| 項目 | 怎麼驗證 |
|---|---|
| Llama 3.3 會不會正確呼叫工具、參數格式對不對 | `python -m evals.run_eval` 的 22 題 |
| 驗證 Agent（Mistral Small 3.1）會不會誤判或漏判 | 同上，看「AI 首稿問題」欄 |
| Cloudflare 的工具呼叫格式和沙盒模擬是否一致 | 同上；若 Llama 把工具呼叫寫成文字，`aguo/llm.py` 會撿回來，但這段尚未用真實 API 驗證 |
| 回答速度（每題多一次驗證呼叫） | 實際操作 `python -m aguo chat` |

## 四、檢查機制的限制（要誠實說明）

1. 三道檢查保證的是「說出來的都有根據」，不保證「回答有幫上忙」。假 LLM 只回「由顧問確認」也能通過檢查，所以還要用題庫評測回答的完整度。
2. 證據比對看的是數字、單位、燈號、人名、時間和「已完成」的說法；其他語意錯誤靠驗證 Agent，而驗證 Agent 本身也是 LLM，可能誤判。
3. 資料全部是模擬的，價格與規則和原型一致，但不是全國電子的正式資料。

| D12 | 陷阱 | 程式檢視 | 門檻沒量到（或量測不可用）時，走道只算「偏暗」顯示黃燈，其實可能是紅燈 | 燈號維持和原型相同，但加註「量到後走道可能變紅燈」 |

| D14 | 設計限制 | 幾何測試 | 手機 AR 抓不到只有幾公分高的門檻 | AR 只量地面距離，門檻用卡片近拍或捲尺 |
