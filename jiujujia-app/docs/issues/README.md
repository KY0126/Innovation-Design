## Readiness 檢查紀錄（spec-owner）
每個 issue 已檢查：預期行為、輸入邊界、錯誤處理、跨領域合約、不在範圍。檢查時補上的決定：

- **#1**：自行註冊只開放「家人」「長輩」，門市角色由管理者建立，避免任何人註冊成生活顧問。
- **#2**：長輩用 6 碼邀請碼加入長輩家。這是「只有長輩本人能同意」的前提：長輩要有自己的帳號，系統才知道誰是本人。
- **#4**：燈號門檻是暫定值，標註「待確認」，改數值要同步改單元測試；燈號一定要附文字，不只靠顏色（考慮長輩的辨色能力）。
- **#7**：數量可到小數一位（坪數），金額一律整數元。
- **#8**：家人看得到報價，但沒有同意按鈕。

課程建議再用 Gemini 或 ChatGPT 檢查一次：把 issue 內容貼上並問「這個 issue 是否足以讓工程師實作？列出不清楚或缺少的資訊」。
