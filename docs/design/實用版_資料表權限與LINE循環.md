## 1. 整體架構

| 部分 | 放哪裡 | 說明 |
|---|---|---|
| 網頁（Demo 版與實用版） | GitHub Pages（Innovation-Design repo） | 實用版入口 `/live/app/`、`/live/admin/`，已上線骨架 |
| 資料庫與帳號 | Supabase 新專案 `jiujujia-live` | PostgreSQL＋列級權限；資料表定義放 repo 的 `supabase/` |
| LINE 登入 | LINE Developers｜五子登科 Provider｜新增一組 LINE Login 設定，**綁定現有五子登科官方帳號** | 不另開官方帳號；登入畫面顯示五子登科名稱與頭貼；登入的人與好友是同一個 LINE ID |

| 現有 LINE 選單與 12 則自動回覆 | 維持不動 | Webhook 不打開（打開會讓關鍵字自動回覆失效） |

## 2. LINE 登入流程（家庭）

1. 未登入時點到要登入的功能，跳出登入提示方框（已完成），按「確認」。
2. 轉到 LINE 登入頁；畫面上有「加入五子登科好友」選項（D3），加的是現有五子登科官方帳號，已是好友的人不會再問。
3. 使用者同意後回到 `/live/app/`，網址帶著 LINE 給的一次性代碼。
4. 網頁把代碼交給 Edge Function `line-login`。Edge Function 向 LINE 換取並驗證身分，在 Supabase 建立或找到這個帳號，再發一張 Supabase 登入憑證回網頁。
5. 網頁拿到憑證就算登入完成，回到剛才點的功能（例如「揪居家」）。
6. 第一次登入：沒有家庭時，揪居家顯示「建立長輩家，開始免費評估」與「我有邀請碼」（S01 第三版 C3）。

金鑰（Channel secret）只放 Supabase secrets，網頁、聊天、GitHub 都不出現（C7）。

## 4. 權限（列級權限規則）

| 角色 | 看得到 | 能改 |
|---|---|---|
| 家庭成員 | 只看自己所屬家庭的 T2～T10 | 自己家庭的評估、預約、同意、「我很好」 |
| 長輩（有帳號時） | 自己家庭的報價與關懷事件 | 同意報價、回覆「我很好」 |
| 生活顧問 | 綁定自己門市的家庭 | 報價（T7）、預約狀態（T6） |
| 技師 | 只看指派給自己的工單（T9）與該家庭地址以外的必要資訊 | 自己工單的狀態與驗收 |
| 總部 | 試點指標（彙總數字） | 員工帳號 |
| 任何人（不登入） | 公開的揪心願作品與支持人數（不顯示支持人是誰） | 無 |

- 支持揪心願（T12）、分享（T14）要登入。
- 每條規則都寫一項安全測試（L6）：例如 A 家庭的帳號查 B 家庭資料，必須被拒絕。
- 示範資料不寫進 Supabase（R15）；測試用另一個 Supabase 分支，不碰正式資料（Q10）。

## 5. LINE 完整循環

### 5-1 分享卡片（從 App 分享出去）

| 編號 | 創新 | 什麼時候出現「分享」 | 卡片內容 | 對方點開後 | 不放的資料 |
|---|---|---|---|---|---|
| S1 | 創新一 | 完成評估、看到燈號報告時 | 「爸媽家的居家安全評估好了：3 紅 2 黃，一起看看怎麼改善」＋按鈕「加入一起看」 | 登入並帶入邀請碼，加入同一個長輩家；雙方觸發家人邀請禮 | 平面圖、地址、尺寸、長輩姓名 |
| S2 | 創新二 | 每月 1 日（家庭已啟用夜間關懷） | 「這個月爸媽家平安：夜燈 31 天正常，0 次異常」＋按鈕「看完整紀錄」 | 已是家人：直接看；不是家人：要邀請碼 | 作息時間、房間位置 |
| S3 | 創新三 | 拼好揪心願、或支持別人的心願後 | 「我拼了一個心願：○○○，還差 12 人就能預購」＋按鈕「我也需要」 | 不登入可看作品與人數；按「我也需要」才登入（順便加好友） | 拼的人的姓名（只寫「一位子女」） |

卡片一律寫「揪居家／五子登科」，不寫「全國電子」（C8）。卡片上的數字一律來自資料庫，沒資料就不出卡片（R15）。

### 5-2 官方帳號推播（回訪）

| 編號 | 觸發時機 | 收件人 | 訊息 | 點了到哪裡 |
|---|---|---|---|---|
| P1 | 生活顧問送出正式報價 | 家庭全部成員 | 「爸媽家的改善方案好了，請長輩確認」 | 報價頁 |
| P2 | 預約確認、技師出發、施工完成 | 子女 | 「技師今天 14:00 到府」等 | 進度頁 |
| P3 | 夜間關懷偵測到異常 | 先問長輩 | 「昨晚還好嗎？」＋按鈕「我很好」 | 一頁式回覆頁（不用登入，連結一次有效） |
| P4 | 長輩 30 分鐘沒回覆 P3 | 子女 | 「媽媽還沒回覆，要不要打個電話？」 | 關懷事件頁 |
| P5 | 保養到期前 7 天 | 子女 | 「夜燈電池該換了，預約到府？」 | 預約頁 |
| P6 | 揪心願到達 20／50／100 人門檻 | 所有按過「我也需要」的人 | 「你支持的心願到 50 人了」 | 作品頁 |
| P7 | 家人透過邀請碼加入 | 邀請人與被邀請人 | 「哥哥加入了爸媽家，小禮已記錄」 | 家人頁 |

- 推播只送給已加好友的人（T1 的「是否已加好友」）；沒加好友的人只在 App 的通知鈴看到。
- 「我很好」用推播裡的按鈕打開網頁回覆，不靠聊天室，所以 Webhook 維持關閉。
- 額度估算：每戶每月約 10～15 則，3 戶約 45 則，在免費 200 則內（D5）。

## 6. 量 POC 的數字從哪裡來

| 指標（PRD） | 算法 | 資料表 |
|---|---|---|
| 評估完成數 | 有燈號結果的評估數 | T5 |

## 7. 實作順序（第 5～7 步）

1. 你同意後，開 Supabase 專案 `jiujujia-live`（D1）。
2. 你同意後，在五子登科 Provider 下新增 LINE Login 設定並綁定現有五子登科官方帳號，設定轉址網址與加好友選項；金鑰由瀏覽器直接存進 Supabase secrets。
3. 建 14 張資料表與權限規則，寫安全測試。
4. Edge Function：`line-login`（換憑證）、`line-push`（推播）。
5. 網頁接上：登入方框的「確認」改成 LINE 登入；登入後揪居家內容照 S01 第三版 C3。
6. 分享卡片 S1～S3 與推播 P1～P7 先做 S1、S3、P1、P3、P4（主線最需要的），其他放第三階段。
7. 開 PR，測試全過後等你說「合併」。

## 8. 不做

- 金流（實用版用「已付款」狀態模擬，O4 待確認）。
- 打開 Webhook、聊天機器人。
- 家電檔案、購物車、AI 對話。
- 把示範資料或真實家庭資料放進截圖、計畫書（R15）。

## 9. 風險

| 風險 | 處理 |
|---|---|
| Supabase 免費專案閒置 7 天會暫停 | 試點期每天有人用就不會；交件前一天手動喚醒 |
| 推播超過 200 則 | 先只開 P1、P3、P4；超過時改為只在 App 通知鈴顯示 |
| 長輩沒有 LINE | D6：子女代為操作並留紀錄 |
| LINE Login channel 審核或設定延遲 | 第 5 步越早開始越好；延遲時先用 Email 登入讓試用家庭開始用 |
