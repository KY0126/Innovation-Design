# 實用版：Live 版全功能搬遷設計

> 2026/11/26｜決定：同一套畫面換資料來源；四種身分分批全搬
> v2 修改：2D／3D 圖面改用各家真實格局（第 1 批先標「示意格局」，第 2 批顧問到府畫格局）；Demo 不改寫、AR 維持展示，Live 真實量測用 `live-measure.js`；員工帳號改用員工編號登入
> 目標：Live 版（`/live/app/`、`/live/admin/`）和 Demo 版有一樣的首頁 Icon、一樣的全部畫面與功能，但資料存在 Supabase、真的登入、真的通知

---

## 1. 做法

| 項目 | Demo 版（現在） | Live 版（搬完後） |
|---|---|---|
| 畫面 | `app.html`、`admin.html`、`consultant.html` 全部畫面 | **同一套檔案、同一套畫面**，不另外做 |
| 資料來源 | 瀏覽器內的 sql.js 模擬後端（`backend.js`＋`store*.js` 攔截 `/api/…`） | 新增 `live-api.js`，在 Live 模式攔截同樣的 `/api/…`，改呼叫 Supabase |
| 業務規則 | 寫在模擬後端裡 | 簡單讀寫：資料表＋列級權限（RLS）；有狀態轉換或要防作弊的（報價、派工、驗收、點數）：Postgres 函式（RPC），必要時 Edge Function |
| 登入 | 一鍵示範帳號 | 家庭：LINE 登入（已設好，11/26）；生活顧問、技師、總部：員工編號＋密碼（例 `E100001`），由總部在後台建立 |
| 示範專用 | 示範資料、一鍵登入、導覽「幫我點」、重設示範 | Live 全部隱藏；導覽改成只指路、不代按（S09） |

畫面不重做的好處：首頁 Icon、揪居家各入口、3D／2D 圖面、AI 顧問阿國都自動一致，之後改一次兩邊都生效。

兩個例外：
- **AR 量測**：Demo 是展示用，維持示範動畫與範例數字，不需要真的量；Live 用 `live-measure.js` 真的量（一次量完、AR 量高度、標插座、材質確認），在 Live 模式時由同一個「AR 量測」入口打開。
- **2D／3D 圖面**：Demo 全部畫同一間範本房子（`cad.js`，9 m × 9 m、七個空間）。Live 是真的家庭，不能每家都顯示同一張格局，處理方式見第 3-1 節。

## 2. 資料表

- Demo 模擬資料庫約 56 張表；Live 的 `jjj` 區目前 14 張。
- 每一批只加那一批用到的表，沿用 `jjj` 區的規則：尺寸存 mm、不存影像、每張表都開 RLS、欄位層級限制誰能改什麼、附權限檢查腳本。
- 不搬的表：`sessions`（改用 Supabase 登入）、示範重設相關。

### 3-1. 2D／3D 圖面：各家真實格局

| 階段 | 家人看到的圖 | 資料來源 |
|---|---|---|
| 顧問到府前（第 1 批起） | 範本格局，圖上明標「示意格局，顧問到府後換成您家的格局」；疊上家人 AR 實量的走道寬、門檻高、床到浴室距離、插座數 | `cad.js` 範本＋`assessments.dims` |
| 顧問到府後（第 2 批起） | 您家的真實格局：2D 施工圖、3D 鳥瞰、夜間模擬、方案設備標記 | 新資料表 `jjj.floorplans`（顧問畫） |

**格局編輯器（顧問後台，第 2 批）**

| 要做 | 先不做 |
|---|---|
| 拉矩形房間、命名、選地板材質（木地板／止滑磚）、天花高度 | 斜牆、不規則形狀 |
| 放門（含開門方向）和窗 | 多樓層 |
| AR 量到的走道寬、門檻高自動標到對應位置 | 家具自由擺放（先用範本家具） |
| 方案設備標記（夜燈、感測器、插座）放在真格局上 | 格局版本比對 |

- 格局存成和 `cad.js` 範本相同的格式（房間、位置、大小 mm、地板、天花高），`cad.js` 改成可傳入格局，2D 施工圖、`cad3d.js` 3D 鳥瞰、夜間模擬不用重寫。
- `jjj.floorplans`：一家一份（household_id 唯一），本門市生活顧問可新增、修改；家人、指派技師只能看；總部看全部。開 RLS，附權限檢查。
- 不存照片，只存尺寸與房間資料（M3 不變）。
- 退路：12/6 前做不完自由拉房間，先做「從範本挑格局（2 房、3 房、套房）＋改房間尺寸」，2D／3D 一樣顯示接近真實的格局。

## 4. 每一批怎麼驗證和 Demo 一樣

- 同一個流程在 Demo 模式和 Live 模式（模擬 Supabase）各跑一次，比對畫面上的關鍵結果（燈號、報價金額、工單狀態）。
- 權限檢查：家庭看不到別家的資料、技師只看得到派給自己的工單、顧問只看得到自己門市。

## 6. 風險與限制

- Demo 版本身不改寫，維持展示用（示範資料、AR 示範動畫照舊）。要做的是讀懂 Demo 模擬後端（打包後的程式）裡的規則，在 Live 這邊用 Supabase 重做一份；每支 API 都要有測試對照，避免同一個畫面在兩邊算出不一樣的結果（燈號、報價金額）。
- 員工帳號：免費方案的 Supabase 登入夠用；第 4 批前要先建好試點門市的顧問、技師帳號。
- 第 2 批多了格局編輯器，工作量變大；12/6 做不完就用 3-1 節的退路。
- 12/14 很緊；如果第 1、2 批延誤，第 4 批的總部後台先保留現在 `live-admin.js` 的正式報價功能頂著。
