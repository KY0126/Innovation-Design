# 測試規範

> GitHub Actions 依序跑 Lint、單元、整合、系統（E2E）、驗收，前一段沒過就停；全過才開 PR。2026/11/26 確認。

## 條目

| 編號 | 段 | 條目 |
|---|---|---|
| Q1 | Lint（程式） | ESLint 只檢查 `jiujujia/*.js`（不含 `vendor/`）；html-validate 只抓結構錯誤；不開自動排版 |
| Q2 | Lint（程式） | 現有程式先記成基準線，只檢查新改的地方；「真的會出錯」的舊問題列清單給使用者 |
| Q3 | Lint（用語） | 自寫檢查腳本，規則讀 `用語規範.md` 的「不用」欄；LINE 素材掃「全國電子」；掃箭頭 → |
| Q4 | 單元測試 | Node 內建測試工具；領域鐵律標 ★ 的每條至少一個測試 |
| Q5 | 單元測試 | 圖面計算（圖框、離牆距離、照亮比例）、模擬後端讀寫、LINE 選單按鈕不重疊也不超出 2500×1724 |
| Q6 | E2E | 沿用 Playwright 電腦版＋手機版；新增「冒煙」標籤（主線約 10 項、2 分鐘內） |
| Q7 | E2E | 重要畫面加截圖比對：3D、平面圖、關燈看看；3D 用軟體算圖 |
| Q8 | E2E | 改畫面文字就同步改測試 |
| Q9 | 計畫書 | 改完重建 Word／PDF，核對頁數不變，換圖不縮圖 |
| Q10 | 兩個版本 | 系統與驗收測試在 Demo 模式跑全部；實用版另跑主線驗收，連測試用的 Supabase 專案（不碰正式資料）；安全層加測 Supabase 列級權限 |

## 測試分層

| 編號 | 層 | 這個專案測什麼 | 何時跑 |
|---|---|---|---|
| L1 | 單元（`tests/unit/`） | 單一規則與計算：燈號、價格、門檻、圖面幾何 | 每次推送 |
| L2 | 整合（`tests/integration/`） | 模組串在一起、不開畫面：模擬後端 `/api` 跨表流程（建作品、共鳴、達門檻進審查）；Edge Function 對假的 LINE API | 每次推送 |
| L3 | 系統（E2E，`e2e/`） | 整個 App 在瀏覽器裡跨角色走完：家庭、生活顧問、技師、總部；電腦版＋手機版 | 推送跑冒煙，開 PR 跑全部 |
| L4 | 驗收（`tests/acceptance/`） | 產品需求文件每條驗收條件一個測試，標對應的 User Story；另記真人驗收（5 位家人易用性測試、SUS ≧ 68） | 開 PR；真人驗收 12 月第一週 |
| L5 | 回復（`tests/nonfunctional/recovery/`） | 示範資料重設後能重建；本機資料毀損時回到示範資料不白屏；3D 載入失敗顯示提示；LINE 選單程式重跑結果一樣 | 每晚＋手動 |
| L6 | 安全（`tests/nonfunctional/security/`） | 掃金鑰外洩（gitleaks）、套件漏洞（npm audit）；輸入 `<script>` 的心願標題要被跳脫；家庭帳號開不了企業管理端、技師只看得到自己工單 | 每次推送 |
| L7 | 壓力（`tests/nonfunctional/stress/`） | Edge Function 與實用版 Supabase API 用 k6 小量並發（上限 50）；白板放 200 個零件仍可拖曳。不壓 GitHub Pages，也不壓 LINE API（有用量限制） | 手動、只對測試環境 |
| L8 | 效能（`tests/nonfunctional/performance/`） | Lighthouse 手機版預算：首屏最大內容 ≦ 2.5 秒、主執行緒阻塞 ≦ 300 毫秒；3D 首次算圖 ≦ 3 秒；模擬後端啟動時間 | 每晚＋開 PR 時比較 |

現況（2026/11/26）只有 L3（111 項）；L4 要等產品需求文件寫完才有驗收條件可對，L7 在實用版接 Supabase 前只做前端部分。

## 修正流程

1. 重現：本機跑同一個測試，確認真的會壞。
2. 分類：
    - 程式錯：修程式。
    - 測試過時（例如改字沒改測試）：改測試，PR 寫明原因。
    - 偶發失敗：記進偶發清單，限期修好。
3. 先補一個會失敗的測試，再修；修好後測試留下。
4. 各段全部重跑，都過才開 PR，PR 範本貼測試結果。
5. 不能做：刪測試、放寬檢查條件、把 GitHub Actions 改成失敗也算過；一定要放寬或刪除時先問使用者。

## 本機怎麼跑

- 系統測試：repo 根目錄 `python3 -m http.server 8766`，再到 `e2e/` 執行 `npx playwright test`。
- 其他各層的指令在建立測試基礎（下一個 PR）時補上。
