# 資料模型

> 模擬後端目前約 55 張資料表；這裡只寫主線用到的實體與重要規則。2026/11/26 確認。

| 編號 | 實體 | 資料表 | 重點欄位／規則 |
|---|---|---|---|
| M1 | 帳號與角色 | `users`、`users_v2`、`roles_v2`、`sessions` | 同一登入頁依身分分流：家庭、生活顧問、技師、總部 |
| M2 | 家庭與成員 | `households`、`members`、`invites` | 子女付費、家人收通知、長輩本人確認 |
| M3 | 居家評估 | `assessments`、`assessment_drafts` | 尺寸以 mm 存；來源標 AR 或手動；只存尺寸與平面圖，不存影像 |
| M4 | 方案與報價 | `plans`、`plan_versions`、`quotes`、`quote_selections` | 正式報價有版本號；長輩同意的是電腦版正式版本 |
| M5 | 同意紀錄 | `consents` | 每次同意留紀錄；鏡頭需長輩書面同意 |
| M6 | 預約與工作包 | `bookings`、`work_packages`、`site_diffs`、`acceptances`、`acceptance_results` | 協力工班先動工、全國電子技師後安裝；差異要核准 |
| M7 | 設備與關懷 | `devices`、`device_links`、`care_events`、`notifications`、`reminders` | 異常先問長輩再通知家人 |
| M8 | 訂單 | `orders`、`cart_items`、`preorders` | 兩條路：揪居家內結帳／加入購物車；都在會員中心「購買紀錄」 |
| M9 | 揪心願作品 | `wish_works`、`wish_cparts`、`wish_supports`、`wish_updates`、`wish_comments`、`wish_points`、`wish_topics`、`wish_themes` | `build` 是零件陣列：零件種類＋mm 座標 x、y；共鳴只計訂閱戶 |
| M10 | 住宅模板 | `cad.js` 常數 ROOMS、WALLS、DOORS、WINS、FURN、CROP | 9 m × 9 m，單位 mm；每個場域有圖框（CROP），2D 與 3D 都只畫圖框內 |
| M11 | 客服與常見問題 | `faq`、`faq_logs`、`support_tickets` | AI 答不了轉真人，對話一起交接 |
| M12 | LINE 選單 | LINE 端（不在本機） | 別名 `tab-jjj`（預設）、`tab-deals`；12 組關鍵字回應（見最終版 zip `10_LINE官方帳號_五子登科/README.md`） |

## 共用數字

價格、門檻等會被多處引用的數字（見領域鐵律 R7、R8），集中放一份設定檔，程式與單元測試都從這裡讀；數字改了只改一處（例如 11/27 交流會後重算）。

## Demo 版與實用版

- Demo 版：上表全部在瀏覽器內的模擬後端。
- 實用版：主線實體（M1–M9）搬到 Supabase，加列級權限（家庭只看得到自己家、技師只看得到自己的工單）；示範資料不寫進 Supabase。
